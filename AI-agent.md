# Правило для констант и типов

- Хранить константные объекты в `constants.ts`, а типы — в файле типов внутри `type/`; не смешивать их. `type/index.ts` только реэкспортирует типы.
- Выводить типы из констант, если тип описывает значения этих констант.
- Константа не должна импортировать производный от неё тип на том же уровне: это создаёт циклическую зависимость. Если константе нужен тип, объявить этот тип уровнем выше константы и импортировать оттуда.

# Правило для DTO

- Необязательные поля объявлять через `?`, например `login?: string`, а не через `string | null`. Не требовать `null` для полей, которые клиент не передаёт.

# Правило для импортов

- В папках текущей фичи создавать `index.ts`, который реэкспортирует используемые снаружи сущности из файлов той же папки; не переписывать ради этого соседние сервисы.
- Между папками фичи импортировать через `index.ts` папки, например `./utils`, а не `./utils/admin-guard`.
- Внутри одной папки оставлять прямые импорты; не импортировать её собственный `index.ts`, чтобы не создавать циклических зависимостей.
- Если импорт через родительский `index.ts` создаёт цикл, импортировать нужный внутренний файл напрямую вместо добавления циклического реэкспорта.
